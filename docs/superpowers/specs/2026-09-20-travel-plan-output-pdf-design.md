# 旅行规划输出与 PDF 路书设计

- 日期：2026-09-20
- 状态：已确认，待实现
- 适用范围：“我知道去哪”和“帮我决定去哪”共用的旅行规划结果模块
- 设计参考：`travel-guidebook` 技能、暖色羊皮纸路书规范、高德静态地图与 URI 导航
- 修订说明：时间轴生成与雷达数据来源由 `2026-09-21-ai-butler-guidebook-design.md` 取代/补充；本设计继续约束固定输出结构、降级顺序、历史引用白名单与 PDF 版式。

## 1. 目标

旅行规划结果不是一个静态攻略，而是一份可以直接照着执行的行程。用户需要知道每天几点出发、下一站去哪里、坐什么交通、吃什么、在哪里休息、晚上住哪里、预计花多少钱，以及为什么安排这些内容。

“我知道去哪”和“帮我决定去哪”最终都生成统一的 `TripPlan`，共用天气、交通、预算、景点审核、时间轴、导航和 PDF 导出能力。

## 2. 非目标

- 不实时查询火车、飞机和轮船班次。
- 不预订酒店、门票或交通。
- 不承诺门票、酒店、停车和交通价格一定准确。
- 不为每个景点制作单景点雷达图。
- 不把 AI 估算伪装成实时数据。
- 不保存 PDF 文件到云端；“保存”仅保留行程数据，PDF 直接下载到本地。

## 3. 两种入口

### 3.1 我知道去哪

用户填写：

- 目的地
- 出发地
- 出发日期和天数
- 每日出发时间和最晚结束时间
- 成人数和儿童数
- 全团总预算
- 途经点，最多 5 个
- 交通方式、经济/均衡/效率偏好
- 是否往返、快速返程或回程再玩
- 旅行节奏、兴趣和自驾车辆能源类型

### 3.2 帮我决定去哪

通过分步问题收集同一组必要数据，并推导目的地。问题包括：

1. 风景方向
2. 天数
3. 节奏
4. 体验偏好
5. 出发地
6. 出发日期
7. 交通优先级
8. 往返方式

两种入口最终调用同一个旅行规划模块。

## 4. 统一输出结构：TripPlan

```ts
type TripPlan = {
  meta: TripMeta;
  budget: TripBudget;
  route: TripRoute;
  days: TripDay[];
  closing: TripClosing;
};
```

### 4.1 TripMeta

- 标题
- 出发地、途经点、目的地
- 出发日期、总天数
- 成人数、儿童数
- 人均预算
- 交通偏好
- 旅行节奏
- 兴趣标签

### 4.2 TripBudget

- 全团总预算
- 预计总费用
- 剩余或超支金额
- 人均预算
- 人均预计费用
- 分类预算：交通、住宿、餐饮、门票、其他

“其他”默认按前四类费用合计的 10% 预留，最低 ¥200；用户填写具体金额时使用用户值。

### 4.3 TripRoute

- 高德全程静态地图
- 去程节点和返程节点
- 去程交通线、返程交通线
- 距离和耗时
- 每段交通方式和导航链接
- 往返模式：快速返程、回程再玩、单程

### 4.4 TripDay

- 日期
- 当日主题
- 天气
- 每日地图
- 高德导航链接和二维码
- 时间轴节点
- 当日费用
- 当日综合雷达
- 今日目的、核心重点和注意事项

### 4.5 TripTimelineNode

```ts
type TimelineNodeType =
  | "transport"
  | "transfer"
  | "attraction"
  | "meal"
  | "rest"
  | "hotel"
  | "night-activity";
```

节点必须包含：

- 开始时间和结束时间
- 地点及高德坐标
- 交通方式和预计耗时
- 停留时长
- 预计费用
- 节点类型
- 关键提示
- 高德导航链接

## 5. 时间轴规则

排程职责：由 DeepSeek 在用户人数、预算、交通与节奏条件内排出完整时间轴；本地只做确定性校验，并在发现违规时最多发起 1 次携带违规清单的重排。标题、摘要与每日排程同源。

> 本节中涉及时间轴生成与重排职责的部分，由 [2026-09-21 AI 管家式路书生成设计](./2026-09-21-ai-butler-guidebook-design.md) 取代/补充。

- 轻松：使用上午、中午、下午、晚上等宽松时段，不强制分钟级时间。
- 适中：关键节点显示时间，可浮动。
- 充实：显示完整 `09:00–11:30` 时间轴。
- 默认每日时间：轻松 `09:30–19:30`、适中 `08:30–21:00`、充实 `08:00–22:00`。
- 用餐、休息、酒店入住和当晚住宿均是正式时间轴节点。
- 夜游和夜间活动计入当天，顺序为晚餐 → 酒店入住 → 可选夜游 → 返回酒店 → 今日总结。

## 6. 景点审核

DeepSeek 对每个景点执行一次审核，输出：

- 景点规模：小型、中型、大型、跨日型
- 建议停留时间
- 体力强度
- 亲子适宜度
- 天气敏感度
- 最佳游玩时段
- 拥挤程度

分类：

- 小型：1–2 小时
- 中型：半天，3–5 小时
- 大型：全天，6–10 小时
- 跨日型：2 天及以上

跨日景点占用每个旅行日的核心景点额度，不与其他大型景点硬塞在同一天。跨日景点在 PDF 中作为一个连续跨页专题展示，内部拆分每日执行计划。

## 7. 当日综合雷达

PDF 每天只展示一个当日综合雷达，不再为每个景点单独绘制雷达。

- 五层同心五边形，分值为 20、40、60、80、100。
- 五个顶点显示：体力、亲子、天气、时间、拥挤。
- 属性名和数值必须完整显示，不能裁切。
- 五个分值来自 2026-09-21 设计定稿的骨架数据；本地仅按模板映射到五层刻度，不再进行相对拉伸或重排。
- 高分为“更明显、更需要关注”，并不统一代表好坏。
- 每日雷达放在 PDF 左页地图、住宿和预算信息之后。

> 本节中涉及雷达数据来源与本地处理方式的部分，由 [2026-09-21 AI 管家式路书生成设计](./2026-09-21-ai-butler-guidebook-design.md) 取代/补充。

## 8. 预算规则

- 用户填写全团总预算。
- 系统计算成人、儿童差异后的预计总费用。
- 儿童默认与成人同住，不单独增加房间数；成人超过 2 人时按两人一间推算。
- 自驾增加车辆能源类型：燃油、纯电、混动。
- 自驾费用由 DeepSeek 综合估算能源费、高速通行费、节假日免费情况、停车费。
- 火车、飞机、轮船的成本和时间由 DeepSeek 估算，不查询具体班次。
- 预算不足时按以下顺序自动降级：住宿档次 → 付费景点或体验 → 餐饮标准 → 交通方案 → 低优先级途经点。
- 效率优先模式下，不自动牺牲交通时间。
- 若无法压到总预算以内，明确提示超额金额，并建议提高预算、减少景点或删减途经点。

## 9. 交通规则

- 高德负责自驾、步行、骑行、公交和地铁的路线、距离与耗时。
- 火车、飞机和轮船只需通勤估算，不查询具体班次。
- DeepSeek 按经济、均衡、效率三种偏好估算通勤时间和成本区间。
- 每个节点和交通段提供“打开高德导航”。
- PDF 中提供可点击导航链接和二维码。

## 10. 途经点规则

- 全程地图按起止顺序显示途经点。
- 小型途经点直接进入当天时间轴。
- 中型途经点作为当天核心停靠点。
- 大型或跨日途经点增加独立专题页。
- 返程途经点与去程途经点分别计算，不共用同一段交通数据。

## 11. PDF 页面设计

PDF 使用 `travel-guidebook` 技能生成：

- 羊皮纸暖色背景
- Noto Serif SC 标题、Noto Sans SC 正文、JetBrains Mono 功能信息
- Tabler Icons
- 内联 SVG 装饰
- 不使用 AI 插图或 emoji
- A4 打印、正确分页、保留背景色

### 11.1 总体页面顺序

1. 封面
2. 旅程概览
3. 路线与交通
4. 预算分配
5. 每日行程
6. 数据来源与估算说明
7. 旅行回望与致当代徐霞客
8. 封底

### 11.2 每日双页结构

- 左页：高德每日地图、导航按钮、二维码、今晚住宿、当日预算、当日综合雷达。
- 右页：完整执行时间轴、用餐和休息节点、日末总结。
- 每个旅行日从新的双页开始。
- 内容较多时允许增加 1–2 页或更多页，不压缩重要信息。

### 11.3 今日总结

采用“推荐版”：

- 今日目的：一段较完整的总结。
- 核心重点：按 1 / 2 / 3 编号。
- 每项包含景点介绍、游览重点和适量历史背景。
- 小型景点简述，大型和跨日景点展开说明。
- 注意事项：每天 2–5 条，按重要性排序，可适当多写。
- 关键信息使用加粗、下划线和暖色高亮。
- 页脚固定显示“内容由 AI 生成，旅游记得以实际为准哦”。

## 12. 往返与旅行回望

旅程总结必须从新页开始，页面开头是全程高德地图：

- 去程使用实线。
- 返程使用不同颜色。
- 快速返程：返程使用虚线；若路线重合，标注“快速原路返回”。
- 回程再玩：返程使用独立颜色实线，按实际返程节点绘制。
- 单程：只显示去程，并标注“未安排返程”。

地图后展示旅程总结和评价：

- 基于实际旅行路线、景点、天数、交通和节奏动态生成。
- 引用可核验的古文、历史游记、地方志或诗词，并注明篇名。
- 无合适内容时使用现代语言释义，不伪造原文。
- 主题保持“每一个丈量祖国大好河山的人，都是当代徐霞客”。
- 不同旅行应根据实际路线生成不同评价和不同历史引用。

## 13. 数据来源与降级

- 高德不可用：使用 DeepSeek 估算距离和时间，并标记地图不可用。
- Open-Meteo 失败：切换高德天气；两者都失败才隐藏天气。
- DeepSeek 失败：不生成伪造个性化行程，保留已确认路线和基础信息。
- 静态地图失败：保留导航链接和时间轴。
- PDF 失败：保留可打印 HTML，提供浏览器打印为 PDF 的备用方案。
- 实时数据与 AI 估算必须明确区分。

## 14. 缓存

- 高德 POI：缓存 30 天。
- 高德路线：缓存 7 天。
- 高德静态地图：按路线节点集合和样式缓存。
- Open-Meteo 天气：缓存 1–6 小时。
- DeepSeek 日总结、景点介绍和旅行评价：按行程内容哈希缓存。
- 用户修改目的地、途经点、日期、人数、预算或节奏时，相关缓存失效。

## 15. 安全与隐私

- API Key 仅保存在服务端 `.env`，不进入客户端包。
- 地址、预算、同行人数等只用于行程生成，不写入公共共享地点表。
- 历史引用必须可核验，不能生成虚假原文。
- 所有费用和时间均为估算，展示时不得使用“已确认”“实时价格”等措辞。

## 16. 测试与验收

- 两种入口最终生成相同结构的 `TripPlan`。
- 时间轴覆盖交通、用餐、休息、住宿和夜游节点。
- 景点规模、跨日拆分和排序正确。
- 往返地图能分别绘制去程和返程。
- 预算自动降级顺序正确。
- 用户总预算不足时显示明确超额提示。
- 高德、Open-Meteo、DeepSeek 和 PDF 降级路径可验证。
- PDF 中五边形雷达的属性和值完整显示。
- PDF 每个旅行日从新双页开始，内容多时可扩展。
- 数据来源页和 AI 声明页准确。
- PDF 可直接下载，文件命名清晰。
