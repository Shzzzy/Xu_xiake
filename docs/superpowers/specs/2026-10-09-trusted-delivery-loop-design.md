# 徐霞客旅行规划：可信交付闭环设计

> 状态：已评审，待用户复核。  
> 设计日期：2026-10-09。  
> 适用范围：产品基础、权益结算、路书预览、版本管理、PDF/打印和分享。  
> 不在本设计内：新增 AI 能力、长线逐日扩展、独立 PDF 渲染服务、管理员无限使用实现。

## 1. 设计目标

让用户完成一次可信的旅行交付闭环：

```text
填写旅行条件
  -> 预检并生成草稿
  -> 查看完整或受限路书预览
  -> 确认生成正式版本
  -> 只结算一次权益
  -> 同一版本可重复打印、导出和分享
```

本设计解决四个核心问题：

1. 预览完成前不能扣点。
2. 正式版本必须不可变、可重复访问。
3. 访客、首次免费用户、付费用户和无点数用户应有统一生命周期。
4. PDF、打印和分享必须指向同一份正式版本，不能各自维护一套状态。

## 2. 已确认业务决策

- 1 点按正式成稿版本结算，不按生成尝试结算。
- 草稿阶段不扣点，允许免费修改。
- 同一正式版本的重复打印、导出和分享免费。
- 标题、分享文案和打印设置变化不产生新版本。
- 日期、天数、路线、途经点、人数、交通、预算或核心景点顺序变化产生新版本。
- 访客可以填写条件、生成草稿并查看符合其权益状态的预览。
- 点击“确认生成正式版本”前必须登录。
- 首发 PDF 使用浏览器打印/另存为 PDF，正确处理弹窗拦截和可打印 HTML 降级。
- 一键下载 PDF 后置，需要独立渲染服务。
- 已经用完首次免费且点数不足的登录用户，可以先生成受限预览，再购买或继续使用点数。
- 受限预览的锁定内容必须由服务端不返回，不能只通过前端模糊或隐藏实现。
- 管理员无限使用进入扩展队列，通过角色鉴权和权益旁路单独实现。

## 3. 用户路径

### 3.1 访客首次使用

```text
填写条件
  -> 预检
  -> 生成完整草稿预览
  -> 查看完整路书预览
  -> 点击确认生成正式版本
  -> 登录
  -> 保存正式版本并领取首次免费资格
```

访客草稿必须由服务端保存或签名保存，`sessionStorage` 不能作为事实来源。

### 3.2 已登录且仍有首次免费资格

```text
填写条件
  -> 预检
  -> 生成草稿
  -> 查看完整预览
  -> 确认生成正式版本
  -> 领取首次免费资格
```

### 3.3 已登录且有可用点数

```text
填写条件
  -> 预检
  -> 预留 1 点
  -> 生成草稿
  -> 查看完整预览
  -> 确认生成正式版本
  -> 消费预留 1 点
```

### 3.4 已登录但无免费资格且点数不足

```text
填写条件
  -> 预检
  -> 生成受限预览
  -> 查看总览、预算、日期摘要和第一天完整内容
  -> 购买点数
  -> 从同一草稿继续生成剩余内容
  -> 确认生成正式版本并消费 1 点
```

同一用户同时只能有一个活动的受限草稿。重新生成会替换旧草稿，不额外产生结算。

### 3.5 管理员

管理员无限使用属于扩展功能。当前设计只保留权益旁路扩展点，要求在正式实现时：

- 通过角色鉴权，不能使用硬编码账号或客户端自报角色。
- 正式成稿时记录结算模式为 `admin_bypass`。
- 不消耗首次免费资格和点数。
- 保留操作审计记录。

## 4. 交付状态机

```text
brief
  -> preflight
  -> entitlement_reserved
  -> draft_generating
  -> draft_ready
  -> preview_generating
  -> preview_ready
  -> awaiting_finalize
  -> finalizing
  -> finalized
  -> exporting
  -> exported
```

访客和受限预览路径允许在 `awaiting_finalize` 前完成登录或购买，然后继续原状态。

失败状态必须包含：

- 失败阶段。
- 是否已经释放权益预留。
- 是否可以重试。
- 是否可以从草稿恢复。
- 用户是否已经产生正式消费。

## 5. 事务边界

### 5.1 预留

- 只锁定余额或首次免费资格，不消费。
- 预留绑定草稿、请求指纹和用户或访客会话。
- 设置过期时间，过期后自动释放。

### 5.2 草稿生成

- 保存旅行输入、行程快照、页面校验结果、预览范围和预留引用。
- 生成失败或预览失败时释放预留。
- 不允许在草稿阶段消费免费资格或点数。

### 5.3 正式结算

`FinalizeService` 使用一个幂等事务完成：

1. 校验草稿属于当前用户或访客会话。
2. 校验预览已经通过。
3. 保存不可变正式版本。
4. 记录内容哈希和版本号。
5. 领取首次免费资格或消费付费预留。
6. 将权益流水绑定正式版本。
7. 标记生成凭证已完成。

幂等键为 `draft_id + content_hash`。重复调用返回同一个正式版本，不重复扣点。

### 5.4 导出与分享

- 只读取正式版本。
- 不参与权益结算。
- 同一版本重复导出或分享不收费。
- 导出失败只重试导出，不能回退成草稿或重新消费。

## 6. 版本规则

产生新版本的变化：

- 出发地、目的地和途经点。
- 出发日期、天数和每日时间窗。
- 成人、儿童人数。
- 交通偏好、返程模式、旅行风格。
- 预算上限和自驾能源。
- 行程节奏、兴趣约束。
- 景点选择或核心景点顺序。
- 影响路线、预算、时间轴或页面内容的模型结果。

不产生新版本的变化：

- 标题展示文案。
- 分享文案。
- 打印偏好。
- 页面缩放和局部展示设置。

正式版本不可变。需要修改时创建新草稿，重新预览，再由用户确认生成新版本。

## 7. 受限预览

### 7.1 可见内容

- 行程总览。
- 路线图、总距离和交通方式。
- 总预算和主要预算构成。
- 全部日期的标题、主题和天气趋势。
- 第 1 天完整时间轴、地图、导航和费用。
- 剩余天数和锁定内容数量。

### 7.2 锁定内容

- 第 2 天以后的详细时间轴。
- 第 2 天以后的导航和景点文案。
- 历史背景和深度分析。
- 完整 PDF。
- 分享链接。

### 7.3 安全要求

服务端只返回允许展示的页面和数据。禁止把完整数据发送到浏览器后用 CSS 模糊、遮罩或隐藏元素。

### 7.4 购买后继续

- 用户完成购买后回到原草稿。
- 已完成阶段不重复执行。
- 只生成剩余日期和完整路书页面。
- 最终确认时仍然只结算一次。
- 如果用户放弃购买，草稿按有效期清理，不产生消费。

## 8. 组件边界

### 8.1 DeliveryFlowController

客户端唯一流程控制者，负责状态推进、登录回跳、购买回跳、重试和用户提示。替换当前并行的 `plannerState` 与 `GuidebookGenerationState`。

### 8.2 DraftService

创建、更新、读取和过期草稿；保存输入、计划快照、预览范围和预留引用。

### 8.3 PreviewService

生成和校验路书页面；根据预览范围只返回允许内容。不消费权益。

### 8.4 FinalizeService

执行正式版本保存和权益结算的幂等事务。

### 8.5 TripVersionRepository

提供不可变正式版本的读取、内容哈希、所有权和版本查询。

### 8.6 ExportService

读取正式版本并处理打印、可打印 HTML 和后续 PDF 文件下载。不得包含权益判断。

### 8.7 ShareService

为正式版本创建和解析只读分享链接。不得包含权益判断。

## 9. 数据模型

优先扩展现有表，不一次性重写现有数据库。

### 9.1 TripDraft

```text
owner_user_id nullable
guest_session_id nullable
brief

page_manifest

```

### 9.2 TripVersion

```text

```

## 10. PDF 与分享契约

首发版：

- 主按钮文案为“打印 / 另存为 PDF”。
- 服务端返回 PDF 时正常下载。
- 服务端返回可打印 HTML 时打开或下载 HTML，不能当作失败。
- 打印窗口被拦截时提供可打印 HTML。
- 移动端提供独立打开可打印 HTML 的方式。
- 所有操作只读取正式版本。

后续一键下载 PDF：

- 使用独立浏览器渲染服务。
- 生成任务与正式版本绑定。
- 文件存入对象存储。
- 后续重复下载复用缓存。
- 不在 Netlify Function 运行时启动 Playwright。

## 11. 错误恢复

- 预检失败：不生成草稿，不扣权益。
- 生成失败：释放预留，保留可重试草稿。
- 预览失败：释放预留，显示失败阶段，可重试。
- 结算失败：事务回滚，正式版本不保存，权益不消费。
- 导出失败：正式版本有效，重试不收费。
- 分享失败：正式版本有效，重试不收费。
- 草稿过期：提示重新生成，不产生消费。

## 12. 安全与权限

- 正式版本只能由所有者读取、导出和分享。
- 分享链接只返回只读版本内容。
- 访客草稿使用短期凭证或签名令牌。
- 锁定内容不能发送到浏览器。
- 所有权益和版本操作必须在服务端校验。
- 管理员角色必须由服务端角色判断，不能信任客户端传值。
- 日志不得记录密钥、完整支付信息或敏感身份数据。

## 13. 验收标准

- 首次免费用户预览失败时，免费资格未被消耗。
- 付费用户预览失败时，点数预留自动释放。
- 付费用户确认正式成稿后，只消费 1 点。
- 重复点击 finalize 不会重复扣点。
- 同一正式版本重复打印、导出和分享不收费。
- 账号重新打开旧行程时，无需原始生成凭证即可导出。
- 无点数用户能查看受限预览，购买后从原草稿继续生成。
- 受限预览不包含锁定内容，浏览器请求和响应中不能出现被锁定的正文。
- 打印窗口被阻止时可打印 HTML 仍可打开。
- PDF 请求返回 `status: html` 时，用户得到可使用的 HTML 路径。
- 不同用户不能读取或分享他人的正式版本。
- 桌面和移动端均能完成完整交付流程。

## 14. 实施顺序

1. 建立统一交付状态机和草稿模型。
2. 调整权益预留与正式结算时机。
3. 补齐预览失败释放和 finalize 幂等。
4. 统一正式版本读取、导出和分享契约。
5. 实现受限预览和购买后继续生成。
6. 修正 PDF/打印/HTML 降级路径。
7. 补齐端到端测试和浏览器验证。
8. 单独进入管理员无限使用扩展。

## 15. 本设计明确不做

- 不在首发版实现真实一键下载 PDF。
- 不在本设计内实现管理员无限使用。
- 不在本设计内统一全部预算基准和房间数规则。
- 不把 17 天以上长线扩展为逐日完整路书。
- 不新增支付渠道。
- 不进行 UI 整体重做。
