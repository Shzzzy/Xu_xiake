# 途经点发现与共享灵感景点设计

## 1. 背景与目标

当前行程规划只有目的地会触发 Tavily 搜索。途经点虽然会进入路线结构和 DeepSeek 提示词，但系统不会围绕途经点单独检索资料，因此像“龙岩”这样尚未收录的自由输入地点无法稳定获得本地景点、来源和地区校核。

本设计新增一条完整的数据链路：

1. 识别用户输入的未知目的地或途经点。
2. 对每个未知地点单独搜索资料。
3. 批量调用 DeepSeek 校核名称、地区、类型和置信度。
4. 将高置信度地点写入所有访客共享的灵感景点库。
5. 为动态地点生成稳定且不重复的 SVG 配图。
6. 将校核后的资料合并给最终行程规划器。

## 2. 已确认的产品规则

- 动态灵感景点由所有访客共享。
- 收录对象是用户输入的途经点本身或目的地本身，不把一次搜索返回的所有具体景点逐一建卡。
- DeepSeek 必须参与地点校核，例如确认“龙岩”属于福建省而不是新疆。
- 高置信度结果自动进入共享灵感库。
- 中置信度结果可供当前行程使用，但不展示到共享灵感库。
- 低置信度或存在地区冲突时，不写入数据库，并向用户提示歧义。
- 相同地点只保留一张卡；后续查询补全信息，不重复创建。
- 动态配图采用项目现有的 SVG 旅行插画风格。
- 每个动态地点拥有唯一视觉配置；同一地点始终复用同一张图，不同地点不能分配相同视觉种子。
- 不引入账号，不保存用户身份、行程或其他个人信息。

## 3. 范围

### 包含

- 目的地和途经点的未知地点发现。
- 每个未知地点独立的 Tavily 资料搜索。
- 批量 DeepSeek 地点校核。
- 共享地点数据库与迁移。
- 动态灵感景点卡片。
- 动态 SVG 配图生成与视觉去重。
- 校核成功、候选和失败的 UI 反馈。
- 将途经点搜索资料合并到实时行程规划。
- 长线行程使用校核后的地点资料。

### 不包含

- 用户账号、收藏隔离或私人地点库。
- 人工审核后台。
- 抓取或保存 Tavily 页面中的版权图片。
- 运行时写入本地文件系统。
- 删除全部动态地点、公开批量写入或批量覆盖接口。

## 4. 架构

### 4.1 处理流程

生成行程时使用以下顺序：

1. 从 `RoutePlan` 提取目的地和途经点。
2. 按规范化名称去重，并排除出发地。
3. 依次与静态 `sceneDestinations` 和数据库中的动态地点匹配。
4. 对未知地点执行 Tavily 搜索。
5. 将本轮所有未知地点合并为一次 DeepSeek 校核请求。
6. 根据校核置信度和证据冲突情况决定是否写入数据库。
7. 将所有可用资料合并进最终规划器的搜索资料上下文。
8. 调用原有实时规划器或长线规划器生成行程。

未知地点最多 5 个，与途经点上限一致。单次行程最多增加一次 DeepSeek 校核调用；已有高置信度缓存不需要再次校核。

### 4.2 建议模块

- `src/lib/place-discovery.ts`：名称规范化、地点键、置信度分档和可测试的纯函数。
- `src/lib/place-discovery.server.ts`：Tavily 查询、DeepSeek 校核、动态地点查询与落库。
- `src/lib/scene-art.ts`：从现有生成脚本提取的无副作用 SVG 渲染器。
- `scripts/generate-inspiration-scenes.ts`：继续负责构建时静态 SVG 文件，但复用 `scene-art.ts`。
- `src/lib/live-planner.functions.ts`：在生成实时和长线行程前调用地点发现服务。
- `src/components/planner/PlannerPrototype.tsx`：展示动态卡片和校核反馈。
- `migrations/0002_discovered_places.sql`：共享动态地点表。

数据库模块只能由服务端函数或服务端模块导入，不能进入浏览器代码。

## 5. 数据模型

### 5.1 `discovered_places`

表使用无归属共享模式，不包含 `user_id`。

| 字段               | 类型                                 | 说明                                                      |
| ------------------ | ------------------------------------ | --------------------------------------------------------- |
| `id`               | `text primary key`                   | 动态地点标识                                              |
| `canonical_key`    | `text not null unique`               | `规范化名称 + 地区`，用于去重                             |
| `canonical_name`   | `text not null`                      | DeepSeek 校核后的规范名称                                 |
| `normalized_name`  | `text not null`                      | 用于快速匹配的名称                                        |
| `region`           | `text not null`                      | 校核后的省、市或地区                                      |
| `country`          | `text not null default '中国'`       | 国家或地区                                                |
| `place_type`       | `text not null`                      | 城市、景区、古镇、自然地貌等                              |
| `summary`          | `text not null`                      | 面向用户的简短介绍                                        |
| `tags`             | `jsonb not null default '[]'::jsonb` | 看点与玩法标签                                            |
| `source_snapshot`  | `jsonb not null default '[]'::jsonb` | 实际使用的 Tavily 来源快照                                |
| `confidence`       | `numeric(4,3) not null`              | 0 到 1 的校核置信度                                       |
| `status`           | `text not null`                      | `verified` 或 `candidate`                                 |
| `art`              | `text not null`                      | 现有 `SceneArt` 类型                                      |
| `accent`           | `text not null`                      | 主题色                                                    |
| `visual_seed`      | `integer not null unique`            | 唯一 SVG 视觉种子                                         |
| `route_context`    | `jsonb not null default '[]'::jsonb` | 兼容字段；始终写入 `[]`，相邻路线节点只在内存中供校核使用 |
| `created_at`       | `timestamptz not null default now()` | 首次收录时间                                              |
| `updated_at`       | `timestamptz not null default now()` | 最近更新时间                                              |
| `last_verified_at` | `timestamptz not null default now()` | 最近校核时间                                              |
| `usage_count`      | `integer not null default 0`         | 复用次数                                                  |

建议索引：

- `unique(canonical_key)`
- `unique(visual_seed)`
- `index(normalized_name)`
- `index(status, updated_at)`

### 5.2 数据库行为

- 高置信度结果使用 `verified`。
- 中置信度结果使用 `candidate`。
- `candidate` 只供地点发现服务按精确名称查询，不进入公开灵感列表。
- 后续再次查询时，如果校核升级为高置信度，将已有行更新为 `verified`。
- 低置信度或地区证据冲突时不写库。
- 缓存命中时只增加 `usage_count`，不更新 `last_verified_at`，也不延长候选的 30 天 TTL；只有实际重新校核才更新 `last_verified_at`。

## 6. Tavily 搜索

### 6.1 查询策略

每个未知地点默认执行一个主查询：

```text
<地点> 所属地区 景点 一日游 推荐
```

满足以下任一条件时，增加一个地区校核查询：

- 来源中未出现明确行政区信息。
- 结果包含同名地点或相互冲突的地区。
- DeepSeek 主校核无法形成稳定判断。

补充查询示例：

```text
<地点> 在哪里 省份 所属城市
```

### 6.2 结果限制

- 每个查询最多使用现有 Tavily 规范化逻辑返回的结果。
- 每个地点最多保留 8 条来源参与校核。
- URL 只允许 `http` 或 `https`。
- 搜索请求使用超时和 `Promise.allSettled`。
- 单个地点搜索失败不会阻断其他地点和最终行程。

## 7. DeepSeek 校核

### 7.1 批量请求

每次行程最多提交一次校核请求，请求中可包含多个未知地点。每个地点包含：

- 用户原始输入。
- 规范化名称。
- 前后路线节点。
- 该地点的 Tavily 来源集合。
- 允许使用的来源 URL 白名单。

### 7.2 输出结构

DeepSeek 返回严格 JSON 数组，每项包含：

```json
{
  "inputName": "龙岩",
  "canonicalName": "龙岩",
  "region": "福建",
  "country": "中国",
  "placeType": "城市",
  "summary": "福建西部城市，以客家文化和土楼周边旅行见长。",
  "tags": ["客家文化", "土楼", "山城"],
  "aliases": ["龙岩市"],
  "confidence": 0.96,
  "ambiguous": false,
  "reasons": ["搜索结果和相邻路线均指向福建省"],
  "sourceUrls": ["https://example.com/longyan"]
}
```

所有 `sourceUrls` 必须来自当前地点的 Tavily 白名单。出现白名单之外的来源时整项校核失败。

### 7.3 置信度分档

- `confidence >= 0.85`、地区明确且不存在冲突：`verified`。
- `0.55 <= confidence < 0.85`：`candidate`。
- `confidence < 0.55` 或地区证据冲突：不写库。

同一批地点中可以存在不同分档。单个地点校核失败不影响其他地点。

## 8. 最终行程规划

### 8.1 实时行程

实时规划器的搜索资料由以下内容合并：

- 原目的地搜索结果。
- 已收录动态地点的来源快照。
- 本轮途经点 Tavily 搜索结果。
- 本轮高置信度或中置信度校核摘要。

在现有提示词约束上增加：

- 路线中的每个途经点都必须作为实际停留与游玩节点，不得只当作交通经过点。
- 只能使用已提供来源中的景点与链接。
- 使用校核后的地区和地点类型解释地理关系。
- 不允许自行补写地区、景点或开放信息。

### 8.2 长线行程

长线行程在调用 DeepSeek 前仍执行地点发现和校核。校核后的名称、地区、摘要和标签作为地点资料进入长线提示词。低置信度结果不得作为确定事实写入阶段路线。

### 8.3 失败降级

- Tavily 失败：继续原有行程生成，不写库，并返回提示。
- DeepSeek 校核失败：当前行程可继续使用原始搜索资料，但不写共享灵感库。
- 最终规划失败：沿用现有错误状态，不影响已经确认的高置信度地点。

## 9. 动态配图

### 9.1 SVG 渲染器

将现有生成脚本中的 `render`、`specialRender`、配色调整、镜像、缩放和签名图形提取到 `src/lib/scene-art.ts`。提取后的核心函数必须无文件系统副作用：

```ts
renderSceneSvg(destination, visual): string
```

构建脚本负责把静态地点结果写入 `public/scenes/inspirations/*.svg`。动态地点在前端根据数据库返回的 `art`、`accent` 和 `visual_seed` 生成 SVG 数据 URL。

### 9.2 去重规则

- 每行动态地点必须拥有唯一 `visual_seed`。
- 首次入库时生成候选种子。
- 如果违反唯一约束，使用新的非敏感盐值重新生成，直到成功。
- 同一地点更新资料时保留原 `visual_seed`。
- 自动测试至少生成 100 个种子，确认 SVG 内容哈希无重复。

### 9.3 视觉一致性

动态配图沿用现有主题色、纸感、墨线、云层和地点类型图形。新增地点与静态景点在同一列表中没有明显的风格断层。

## 10. UI 与反馈

### 10.1 灵感景点列表

列表来源统一为：

```text
静态 sceneDestinations + status = verified 的动态地点
```

动态卡片与静态卡片使用同一交互：

- 点击选中为目的地。
- 显示名称、地区、摘要和标签。
- 显示“新发现”标记。
- 可显示校核来源数量。

### 10.2 检索

名称查找和地区筛选同时覆盖静态与动态地点。数据库中 `candidate` 状态的数据不得出现在公开筛选结果中。

### 10.3 行程生成反馈

生成完成后显示简短反馈：

- 高置信度：`龙岩已校核为福建省，并加入灵感景点。`
- 中置信度：`龙岩已用于本次行程，地区信息仍在校核。`
- 低置信度：`龙岩存在地区歧义，本次未收录。`
- 搜索失败：`龙岩资料检索失败，行程已继续生成。`

多个地点使用一条汇总消息或连续消息展示，避免大量重复 toast。

## 11. 安全与隐私

- 复用现有数据库连接层，不新增账号表或 `user_id`。
- 不保存用户身份、IP、设备、行程正文或输入历史。
- 只保存公开旅行地点的名称、地区、摘要、标签、来源和视觉配置；`route_context` 始终为 `[]`，路线相邻节点和任意路线片段不会作为上下文写入共享库，也不会进入 `source_snapshot`。经校核的途经点或目的地本身仍可作为公开地点卡片保存。
- 自由输入名称去除控制字符并限制长度。
- 浏览器只能读取公开的 `verified` 卡片。
- 写入只发生在服务端生成流程内部，不提供公开批量写入接口。
- 不提供删除全部或覆盖全部接口。

## 12. 测试

### 单元测试

- 名称规范化、别名和 `canonical_key`。
- 置信度分档。
- 同名异地地点允许共存。
- 同地点重复收录只产生一行。
- DeepSeek 来源白名单校验。
- Tavily 失败时的降级结果。
- 动态地点与静态地点合并。
- 100 个视觉种子生成无重复。

### 集成测试

- `厦门 -> 龙岩 -> 黄山`：龙岩触发独立 Tavily 查询。
- 龙岩资料明确指向福建时生成 `verified` 记录。
- 冲突资料返回新疆与福建时进入候选或不写库，不标记为确定事实。
- 第二次生成相同路线时复用数据库记录，不重复调用校核。
- 动态地点可作为目的地再次生成行程。
- 搜索失败不会阻止原行程生成。

### 浏览器验证

- 新发现卡片出现在灵感景点中。
- 动态卡片配图与静态卡片视觉一致且内容不同。
- 点击动态卡片可正常选中。
- 桌面和移动端无横向溢出。
- 控制台无未捕获错误。

## 13. 验收标准

1. 未知途经点会触发独立 Tavily 查询，而不是只进入路线文本。
2. DeepSeek 能使用途经点资料来源进行行程规划。
3. DeepSeek 校核能将有充分证据的“龙岩”归入福建。
4. 高置信度地点写入共享库，并在刷新和新的浏览器会话中可读取。
5. 中置信度地点不进入共享灵感列表，但可用于当前行程。
6. 低置信度或冲突地点不写库，并给出明确反馈。
7. 相同地点不会重复建卡，后续查询只补全已有记录。
8. 每个动态地点拥有稳定且唯一的 SVG 配图。
9. 不保存用户身份、行程正文或路线片段；共享行中的 `route_context` 始终为空数组。
10. `npm run typecheck`、`npm test`、`npm run build`、开发环境与生产构建浏览器验证均通过。

## 14. 交付顺序

1. 数据库迁移和地点规范化模块。
2. Tavily 单点检索。
3. DeepSeek 批量校核和置信度落库。
4. 行程规划器接入。
5. 动态灵感卡片和反馈。
6. SVG 渲染器抽取与视觉唯一性。
7. 集成测试、开发环境浏览器验证和生产构建验证。

## 15. 已知环境限制

当前工作区不是 Git 仓库，因此无法按设计流程执行 Git 提交。设计文档仍保存在本文件中，后续实现不依赖 Git 操作。

本地预览在没有 `DATABASE_URL` 时使用进程内的 PGLite。动态景点在当前开发服务进程内由所有访客共享，但开发服务重启后会重置；部署环境使用持久化数据库，跨访客和跨重启保留。
