# 徐霞客旅行规划：业务流程优化讨论稿

> 状态：讨论稿，尚未实施。  
> 基线日期：2026-10-09。  
> 本文只记录流程、事务顺序、PDF 交付和验收口径，不记录真实密钥。

## 1. 核心结论

当前问题不只是“PDF 导出效果不稳定”，而是“行程生成、正式结算、路书预览、导出和分享”没有形成一条统一生命周期。

现有实现会把多个状态混在一起：

- 行程草稿和正式成稿没有明确分离。
- 登录用户首次免费领取、付费点数消费发生在完整路书预览之前。
- PDF 按钮名义上是“生成 PDF”，实际优先打开浏览器打印窗口。
- 服务端返回可打印 HTML 的降级结果，前端没有正确使用。
- 分享依赖正式保存的计划，导出却仍要求生成时的权益凭证。
- PDF、打印、分享和重新下载没有统一绑定到同一个正式版本。

建议将业务核心定义改为：

> 1 点对应一份正式行程版本，不对应一次生成尝试。草稿不扣点，成稿才结算；同一成稿重复导出、打印和分享不再收费。

## 2. 当前真实链路

```text
填写条件
  -> 获取天气
  -> 计算路线
  -> 资格判断或权益预留
  -> 生成行程
  -> 保存计划并完成首次免费领取或点数消费
  -> 状态进入 ready
  -> 逐页生成并预览路书
  -> 点击“生成路书 PDF”
  -> 优先打开浏览器打印窗口
```

三类用户的结算位置并不一致：

| 用户类型 | 当前结算位置 | 风险 |
| --- | --- | --- |
| 登录后首次免费 | 保存计划时领取免费资格 | 预览失败时免费资格已被消耗 |
| 已购买点数用户 | 保存计划时消费预留点数 | 预览失败时点数已经正式扣除 |
| 访客首次体验 | 生成后绑定访客凭证，导出时再领取 | 状态与另外两类不同，流程复杂 |

生成接口在生成异常时会释放权益，这是正确的；但当前缺失的是“生成成功、预览失败”时的释放路径。

## 3. 已确认的主要问题

### 3.1 结算早于可交付结果

`PlannerPrototype` 在计划组装完成后进入 `saving`，随后执行：

- 访客：`finalizeGuestGeneration`
- 首次免费：`claimCurrentPlan`
- 付费：`finishPaidGeneration`

之后才挂载 `GuidebookPreview`。首次免费和付费路径会在预览开始前完成权益固化。

### 3.2 预览失败没有回滚

`GuidebookPreview` 收到错误后只设置界面错误状态，没有调用释放接口，也没有恢复首次免费资格。用户可能已经完成结算，却没有得到完整路书。

### 3.3 “生成 PDF”与实际行为不一致

`use-guidebook-export` 在权益检查后优先调用 `printPreviewDocument`。只要打印窗口成功打开，就直接返回并显示成功，不会执行服务端 PDF 下载。

按钮文案和进度条让用户以为系统会生成并下载文件，实际行为是：

```text
打开浏览器打印窗口 -> 用户自行选择“另存为 PDF”
```

### 3.4 HTML 降级结果没有被正确使用

服务端无法生成 PDF 时会返回：

```ts
{ status: "html", html: "...", message: "可打印 HTML" }
```

客户端将 `status !== "ok"` 统一当作失败。服务端已经准备好的可打印 HTML 因此不可见，也不可下载。

### 3.5 旧行程重复导出契约不一致

服务端导出只需要 `planId` 和当前登录用户：

```text
exportGuidebook({ planId })
  -> 当前用户读取已保存的正式计划
  -> 重新导出
```

客户端却要求 `entitlementToken` 存在。用户以后从账号中重新打开正式路书时，原始生成凭证可能已经不存在，从而无法再次导出。

### 3.6 预算基准不一致

当前代码至少存在两套基准：

| 项目 | AI 推荐预算 | 最终详细规划 |
| --- | ---: | ---: |
| 住宿 | 600 元/间/晚 | 500 元/间/晚 |
| 餐饮 | 150 元/人/天 | 220 元/人/天 |
| 成人门票 | 200 元 | 80 元兜底 |
| 儿童门票 | 100 元 | 按门票参考价计算 |

房间数也存在两种口径：

- 新预算模块：每位同行者一间房。
- `calculateRooms`：成人最多两人一间。

用户先看到推荐预算，再看到最终预算，金额不一致会直接损害可信度。

### 3.7 阶段状态没有接到界面

服务端已实现：

```text
route -> pois -> selection -> timeline -> prices -> budget -> narrative -> pages
```

但 `onStage` 目前只在服务端和测试中使用。界面通过 `GuidebookStage` 播放固定文案，并不反映真实阶段，也没有阶段级失败定位、重试或恢复入口。

## 4. 目标业务流程

```text
填写条件
  -> 预检路线、人数、预算和时间
  -> 创建草稿并只预留权益
  -> 启动作业生成行程
  -> 逐页生成并校验完整路书
  -> 展示冻结的完整预览
  -> 用户确认生成正式成稿
  -> 单次事务保存正式版本并结算
  -> 开放打印、PDF 和分享
```

关键原则：

1. 草稿不扣点，可以免费修改。
2. 预览全部通过后才允许正式结算。
3. 同一正式版本的重复导出、打印和分享免费。
4. 正式版本只依赖 `versionId` 或 `planId` 即可重复访问。
5. 失败、超时和取消必须释放预订权益。
6. 正式版本内容不可变，修改后生成新版本。

## 5. 建议状态机

```text
idle
  -> preflight
  -> entitlement_reserved
  -> generating
  -> draft_ready
  -> preview_validating
  -> awaiting_confirmation
  -> finalizing
  -> finalized
  -> exporting
  -> exported
```

失败状态需要携带：

- 失败阶段。
- 是否已释放权益。
- 是否可以重试。
- 是否可以从草稿恢复。
- 用户是否已经产生费用。

界面不应同时显示两套互相独立的进度条。规划阶段和导出阶段需要明确区分：

```text
规划进度：路线 -> POI -> 时间轴 -> 价格 -> 预算 -> 文案 -> 页面
导出进度：准备素材 -> 生成文件 -> 可下载
```

## 6. 建议事务边界

### 6.1 预留

- 不扣点，只锁定可用余额。
- 将预留绑定到草稿和请求指纹。
- 设置明确超时和自动释放策略。

### 6.2 草稿生成

- 生成完整 `TripPlan`。
- 完整生成并校验所有路书页面。
- 不允许在草稿阶段消费点数或免费资格。

### 6.3 正式结算

在一个事务中完成：

- 保存不可变的正式行程版本。
- 记录内容哈希。
- 领取首次免费资格或消费付费预留。
- 将权益流水关联到正式版本。
- 标记生成凭证已完成。

### 6.4 导出与分享

- 只读取正式版本。
- 不再次消费权益。
- 同一版本重复生成 PDF 可以复用缓存。
- 分享链接绑定正式版本和内容哈希。

## 7. PDF 交付策略

### 7.1 MVP 方案：打印优先

适合当前 Netlify 环境和最快上线：

- 按钮明确命名为“打印 / 另存为 PDF”。
- 导出前验证全部页面到齐、页码连续、没有空白页。
- 提示 A4、默认缩放、开启背景图形、关闭页眉页脚。
- 弹窗被阻止时提供可打印 HTML。
- 移动端提供独立 HTML 打开方式。
- 同一正式版本重复打印不重新扣点。

优点：成本低，复用现有 HTML/CSS，部署简单。  
缺点：用户需要手动选择“另存为 PDF”，不同浏览器结果可能有差异。

### 7.2 正式方案：独立 PDF 渲染服务

如果 PDF 是正式付费交付物，建议：

```text
正式版本
  -> 创建导出任务
  -> 独立浏览器渲染服务
  -> 生成 PDF 并存入对象存储
  -> 返回签名下载地址
```

不要在 Netlify Function 运行时依赖 Playwright 和 Chromium。独立渲染服务可以使用现有 HTML/CSS，但必须建立任务状态、超时、重试和缓存。

## 8. 实施阶段建议

### 阶段一：修正结算顺序

- 新增草稿与正式版本的事务边界。
- 将首次免费和付费消费移动到预览通过之后。
- 预览失败时释放预留权益。
- 保存过的正式版本无需原始生成凭证即可重复导出。

### 阶段二：统一 PDF 契约

- 修正按钮文案和导出状态。
- 正确处理 `status: "html"`。
- 增加页面完整性校验。
- 增加桌面和移动端导出验证。

### 阶段三：统一预算口径

- 推荐预算和最终预算共用同一套价格输入。
- 统一房间数规则。
- 在生成草稿前冻结价格假设。
- 用户修改价格假设时，重新计算受影响阶段。

### 阶段四：接入真实阶段进度

- 将 `onStage` 暴露给前端作业状态。
- 支持阶段级失败提示和重试。
- 支持从已完成阶段恢复，不重复执行成功阶段。

## 9. 建议验收用例

- 首次免费用户预览失败：免费资格未被消耗。
- 付费用户预览失败：点数预留自动释放。
- 付费用户预览成功后确认成稿：只消费 1 点。
- 同一正式版本重复导出 PDF：不再次消费。
- 同一正式版本重复分享：不再次消费。
- 账号重新打开旧行程：无需旧凭证即可导出。
- 打印窗口被拦截：可打印 HTML 仍可打开。
- 服务端 PDF 失败：可打印 HTML 可下载并保留原错误说明。
- 预算推荐和最终预算使用同一住宿、餐饮、门票和房间数口径。
- 13 页及以上路书没有空白页、截断页或双滚动条。

## 10. 待确认业务决策

1. 1 点是否按“正式成稿版本”消费，而不是按生成尝试消费。
2. 同一版本在多少时间内修改或重新生成可以免费。
3. 修改路线、日期、天数或预算后，是否必须生成新版本。
4. 首发版本使用“打印 / 另存为 PDF”，还是必须接入一键下载 PDF。
5. 17 天以上长线是否只提供阶段规划，不提供逐日 PDF 路书。

## 11. 推荐默认口径

- 首次免费和付费都按正式成稿结算。
- 草稿阶段修改免费。
- 同一正式版本重复导出、打印和分享免费。
- 正式内容变化后产生新版本。
- MVP 先把打印路径做正确，正式付费交付再接入独立 PDF 渲染服务。
